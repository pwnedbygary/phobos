# Nintendo 64 diorama — reference notes

This file records the free references the N64 model was measured against, the
documented dimensions, the proportions used in `systems/n64.py`, and the feature
checklist the build is held to. The photo files themselves live in scratch
(`/tmp/n64refs`), not in the repository: no third-party image is shipped or
committed. The model is Phobos's own approximation of the hardware. The owner
asked for the real marks rather than an invented stand-in, so the NINTENDO 64
wordmark, the four-colour N64 logo, the NINTENDO top badge, POWER/RESET,
MEMORY EXPANSION, the port numbers and the cartridge label are reproduced here
as our own typed text and extruded geometry, styled from the reference photos.
No image or font file is copied: lettering is Blender's bundled Bfont converted
to meshes, and the logo is hand-built from four coloured prisms. This is a
reproduction, not a copied asset.

## Feature checklist (the build is held to this)

- [ ] Bulbous charcoal shell: rounded footprint, low front deck, high rear hump,
      lower front lip, side seam/flared bottom edge.
- [ ] Front black panel with the NINTENDO 64 wordmark and the four-colour N64
      logo (typed/extruded here, not a copied image); four oval controller
      ports, two each side, 3 pin holes each and numbers 1–4.
- [ ] Moulded seams on the console (upper/lower shell step) and controller
      (side part-line), plus the top NINTENDO oval badge and the cartridge label
      panel with its NINTENDO mark.
- [ ] Top rear cartridge slot with a raised surround, light-grey slot liner and
      flap, and the ridged/stepped light-grey cartridge inserted ~45 mm.
- [ ] Top vent grille band (20 angled fins) in front of the slot.
- [ ] POWER slider and RESET button in recessed wells, red POWER LED lens.
- [ ] Memory-expansion cover with its small latch and label on the top deck.
- [ ] Side vents, rear multi-out + power jack + vent grille + label, four
      recessed feet and bottom vents.
- [ ] N64 controller: grey three-prong body, dark-grey D-pad, grey analog stick,
      red Start, blue A, green B, yellow C cluster, L/R shoulders, Z trigger
      under the centre, cable to console port 1.
- [ ] Shared 14-inch CRT stage from `crt.py`; one `screen` material with clean
      0..1 UVs; no artwork in the GLB.
- [ ] Plastic not left as flat default-grey CG: authored roughness per part
      (shell/bezel/buttons differ), rounded bevels everywhere, and a moulded
      part-line on the controller and console.
- [ ] 120k–250k triangles, rounded/bevelled, reproducible byte for byte.

## Material contract (seven single-sided materials)

`shell` (light grey: controller, cartridge, port rims, wordmark, label ink),
`dark` (charcoal: console shell, front panel, D-pad, stick well, cable, vents,
feet, and the shared CRT cabinet), `accent` (N64 blue: A and the left leg of the
N64 logo), `accent_light` (N64 green: B and the logo's diagonal), `metal` (satin
warm yellow: C cluster and the logo's right leg), `glass` (red lens: POWER LED,
the red Start button and the logo's lower-right segment), `screen` (the shared
CRT face, `SCREEN`/`SCREEN_GLOW`). The shared CRT's grille bars, knob caps, badge and
vents are given `shell` (a silver-grey trim) in this diorama, so the television
stays silver while `metal` remains the N64's yellow C-button plastic; the GLB
still has exactly the seven materials.

The seven-material contract cannot carry the real console's two dark greys and
the controller's four button colours separately. This build maps the console
body and its front panel both to `dark` (the recess, light port rims and the
wordmark separate them), and the N64's A/B/C/Start colours to `accent`,
`accent_light`, `metal` and `glass`; the deviation is listed in the README and
handoff limits.

## Screen capture for previews

The preview screen is meant to show a real N64 gameplay capture supplied by the
project owner at `refs/screens/n64.png` (scratch). No capture existed when the
geometry was authored; the iteration previews use the shared facsimile frame,
and the build adds `--screen refs/screens/n64.png` when the owner's capture
lands. It is loaded only by the shared
preview rig and is never written into the GLB; the preview PNGs are documentation
only and the capture file itself is not committed. If the capture is absent, the
previews fall back to the generated 16-bit test frame.
